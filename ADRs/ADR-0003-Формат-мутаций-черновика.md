## 1. Контекст

Frontend и backend должны согласованно менять дерево лендинга. Нужен contract-first формат до реализации ([docs#15](https://github.com/rki-mai/docs/pull/15), [docs#16](https://github.com/rki-mai/docs/issues/16)).

**Бизнес-процесс:** редактор добавляет/меняет/удаляет компоненты; клиент отправляет diff как мутации; backend валидирует и увеличивает `version`.

**Out of Scope:** операция `move` как отдельная — заменена частным случаем `update` (parentId/index).

---

## 2. Решение

### 2.1 Формат запроса

```json
{
  "operation": "create | update | delete",
  "data": { }
}
```

### 2.2 Элементы MVP

Типы: `text`, `container`, `link`, `image`, `button`. Id: `lb-*`, корень: `parentId: "root"`.

### 2.3 API

| Метод | Путь | Ответ |
| --- | --- | --- |
| POST | `/api/v1/storage/{project_id}/mutations` | `{ "status": "ok", "version": "N" }` |
| GET | `/api/v1/storage/{project_id}/versions/{version}` | snapshot |

**Schema:** `storage/schema.json` в образе Docker ([PR #12](https://github.com/rki-mai/wb-landing-builder/pull/12)).

---

## 3. Security

- JWT обязателен
- `owner_id` проверяется до применения мутации
- Rate limit: 100 req/min/project; body ≤ 1 MB

---

## 4. Альтернативы

| Альтернатива | Почему нет |
| --- | --- |
| PATCH всего JSON | race conditions, большой payload |
| **Поштучные мутации** | версионирование, меньший трафик | ✅ |
