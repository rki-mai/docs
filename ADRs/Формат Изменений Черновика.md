# Формат представления структуры лендинга (MVP 1.0)

Настоящий документ описывает внутренний формат данных, используемый для хранения, передачи и применения изменений черновика лендинга в генераторе MVP 1.0.

Структура лендинга представляется как плоский список элементов. Каждый элемент является независимой сущностью, имеющей уникальный идентификатор и идентификаторы, указывающие на элементы непосредственно в него вложенные.

## Поддерживаемые типы элементов

В текущей версии поддерживаются следующие HTML-элементы. Каждый из них описывается единым базовым интерфейсом с набором специфичных полей.

### 1. Параграф (`p`)
Используется для отображения текстовых блоков. Соответствует тегу `<p>`.

```json
{
    "element": "text", 
    "id": "lb-1",
    "style": {
        "color": "#333333",
        "fontSize": "16px"
    },
    "value": "Текст параграфа"
}
```

### 2. Контейнер (`div`)
Используется для группировки других элементов и создания макета. Соответствует тегу `<div>`. Не имеет поля `value`, так как служит только оберткой.

```json
{
    "element": "container",
    "id": "lb-1",
    "styles": {
        "display": "flex",
        "padding": "20px"
    },
    "children": ["lb-1"]
}
```

### 3. Ссылка (`a`)
Используется для создания гиперссылок. Соответствует тегу `<a>`.

```json
{
    "element": "link",
    "id": "lb-3",
    "styles": {
        "textDecoration": "underline"
    },
    "value": "Перейти на сайт",
    "src": "https://example.com",
    "children": ["lb-4"]
}
```

### 4. Изображение (`img`)
Используется для вставки графики. Соответствует тегу `<img>`. Поле `value` содержит URL изображения.

```json
{
    "element": "image",
    "id": "lb-4",
    "styles": {
        "width": "100%",
        "height": "auto"
    },
    "value": "https://cdn.example.com/image.jpg",
    "alt": "Описание изображения"
}
```

### 5. Кнопка (`button`)
Используется для интерактивных элементов действия. Соответствует тегу `<button>`.

```json
{
    "element": "button",
    "id": "lb-5",
    "styles": {
        "backgroundColor": "#007bff",
        "color": "#ffffff"
    },
    "value": "Перейти на страницу",
    "src": "https://example.com"
}
```

> Примечание к полям:
>- `id`: Уникальный строковый идентификатор элемента в формате lb-<номер>..
>- `styles`: Объект key-value, содержащий CSS-свойства.
>- `children`: Массив идентификаторов элементов, являющихся вложенными в этот элемент.

## Структура данных и вложенность
Данные хранятся в виде структуры, где каждый элемент содержит поле `children` - массив идентификаторов своих непосредственных потомков. Вложенность определяется не порядком элементов в общем списке, а принадлежностью к массиву `children` родительского узла. Порядок вложенных элементов определяется порядком следования в массиве `children`.

## Основные операции и их описание

В системе управления черновиками лендинга предусмотрены следующие базовые операции для манипуляции структурой данных. Все операции применяются к плоскому списку элементов и требуют соблюдения целостности связей через идентификаторы (`id`). Операции посылаются фронтенд клиентом на бекенд Draft компоненту.

1. **Создание элемента**

Добавление нового элемента в структуру. Запрос должен содержать данные нового элемента и контекст его размещения. Если элемент размещается в корне, то `parentId = root`.

```json
{
  "operation": "create",
  "data": {
    "element": "text",
    "value": "Новый заголовок",
    "styles": {
      "fontSize": "24px",
      "color": "#000000"
    },
    "parentId": "lb-1", 
    "index": 0 
  }
}
```

2. **Обновление элемента**

Частичное или полное обновление свойств элемента. Используется подход PATCH (передаются только изменяемые поля).

```json
{
  "operation": "update",
  "data": {
    "id": "lb-2",
    "fields": {
      "value": "Обновленный текст параграфа",
      "styles": {
        "color": "#ff0000"
      }
    }
  }
}
```

3. **Удаление элемента**

Удаление элемента и всех его вложенных дочерних элементов (каскадное удаление).

```json
{
  "operation": "delete",
  "data": {
    "id": "lb-4"
  }
}
```

4. **Перемещение элемента**

Перемещение элемента и всех его вложенных дочерних элементов.

```json
{
  "operation": "move",
  "data": {
    "id": "lb-5",    
    "parentId": "lb-1",
    "position": 2
  }
}
```

## Обоснование выбора формата JSON для представления структуры лендинга

В ходе проектирования архитектуры было принято решение использовать JSON в качестве основного формата обмена и хранения данных. Ниже приведены основные причины такого решения:

- **Разделение моделей представления и хранения**
  
  Структура данных в редакторе существенно отличается от финального вида публикации. В режиме редактирования элементы содержат множество служебных атрибутов (геометрические параметры, стили рамок, метаданные компоновки и т.д.), которые избыточны для конечного пользователя. Использование JSON позволяет абстрагировать «сырые» данные от их визуального воплощения, храня только семантически значимую информацию.
- **Оптимизация потребления ресурсов**
  
  Хранение данных в формате JSON значительно эффективнее по сравнению с сохранением готовых HTML-фрагментов. HTML-разметка часто включает в себя объемные теги и атрибуты, не несущие полезной нагрузки для бэкенда. Отказ от них позволяет сократить объем занимаемой памяти и ускорить передачу данных между сервисами.
- **Гибкость и независимость от изменений UI**
  
  Архитектура на базе JSON обеспечивает высокую адаптивность к изменениям в дизайне. Например, если требования к отображению текстового блока (<p>) меняются (скажем, текст должен стать жирным), при хранении HTML потребовалась бы сложная миграция базы данных для обновления всех существующих записей. В случае с JSON достаточно внести изменения в логику рендеринга на фронтенде и в сервисе публикации (publish service), оставив хранимые данные неизменными. Это разделяет ответственность за данные и за их представление, упрощая поддержку проекта.

## Пример структуры лендинга

В данном примере рассматривается преобразование HTML-разметки в JSON-структуру с использованием системы уникальных идентификаторов (id). Структура поддерживает вложенность элементов через массив children, что позволяет описывать сложные макеты страниц.

1. **Исходная HTML-разметка**
HTML-код представляет собой визуальное дерево элементов. Корневой контейнер включает заголовок, блок контента (с текстом и кнопкой) и ссылку.
```html
<div id="lb-1" style="display: flex; flex-direction: column; padding: 20px;">
    
    <!-- Заголовок (Heading) -->
    <h1 id="lb-2" style="color: #333; font-size: 24px;">
        Привет, Мир!
    </h1>

    <!-- Контейнер группы элементов (Group Container) -->
    <div id="lb-3" style="display: flex; gap: 10px; margin-top: 20px;">
        
        <!-- Текстовый параграф (Paragraph) -->
        <p id="lb-4" style="color: #666; font-size: 16px;">
            Это пример вложенной структуры.
        </p>

        <!-- Кнопка действия (Button) -->
        <button id="lb-5" style="background: blue; color: white; padding: 10px;">
            Нажми меня
        </button>
        
    </div>

    <!-- Гиперссылка (Link) -->
    <a id="lb-6" href="https://example.com" style="color: blue; text-decoration: underline;">
        Подробнее
    </a>

</div>
```

2. **JSON-представление структуры**
JSON-массив содержит плоский список всех узлов страницы. Связь «родитель-потомок» осуществляется путем перечисления id дочерних элементов в поле children родительского узла.

```json
[
  {
    "element": "container",
    "id": "lb-1",
    "styles": {
      "display": "flex",
      "flexDirection": "column",
      "padding": "20px"
    },
    "children": [
      "lb-2",
      "lb-3",
      "lb-6"
    ]
  },
  {
    "element": "text",
    "id": "lb-2",
    "style": {
      "color": "#333",
      "fontSize": "24px"
    },
    "value": "Привет, Мир!"
  },
  {
    "element": "container",
    "id": "lb-3",
    "styles": {
      "display": "flex",
      "gap": "10px",
      "marginTop": "20px"
    },
    "children": [
      "lb-4",
      "lb-5"
    ]
  },
  {
    "element": "text",
    "id": "lb-4",
    "style": {
      "color": "#666",
      "fontSize": "16px"
    },
    "value": "Это пример вложенной структуры."
  },
  {
    "element": "button",
    "id": "lb-5",
    "styles": {
      "backgroundColor": "blue",
      "color": "white",
      "padding": "10px"
    },
    "value": "Нажми меня",
    "children": []
  },
  {
    "element": "link",
    "id": "lb-6",
    "styles": {
      "color": "blue",
      "textDecoration": "underline"
    },
    "value": "Подробнее",
    "src": "https://example.com",
    "children": []
  }
]
```

3. **Описание логики связей**
- Корневой элемент (`lb-1`): Является контейнером верхнего уровня. В его массиве `children` указаны идентификаторы элементов первого уровня вложенности: заголовок (`lb-2`), контейнер группы (`lb-3`) и ссылка (`lb-6`).
- Вложенный контейнер (`lb-3`): Группирует параграф (`lb-4`) и кнопку (`lb-5`). Эти элементы не являются прямыми детьми корневого элемента, а вложены внутрь `lb-3`.
- Листовые элементы (`lb-2`, `lb-4`, `lb-5`, `lb-6`): Не содержат дочерних элементов (поле `children` пустое или отсутствует), так как являются конечными узлами отображения (текст, графика, интерактивные элементы).
