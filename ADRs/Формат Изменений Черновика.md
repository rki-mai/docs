# Формат представления структуры лендинга (MVP 1.0)

Настоящий документ описывает внутренний формат данных, используемый для хранения, передачи и применения изменений черновика лендинга в генераторе MVP 1.0.

Структура лендинга представляется как плоский список элементов, связанных между собой отношением «родитель-потомок». Каждый элемент является независимой сущностью, имеющей уникальный идентификатор и ссылку на родительский контейнер. Такой подход позволяет гибко манипулировать деревом DOM без необходимости рекурсивной сериализации всего документа при каждом изменении.

## Поддерживаемые типы элементов

В текущей версии поддерживаются следующие HTML-элементы. Каждый из них описывается единым базовым интерфейсом с набором специфичных полей.

### 1. Параграф (`p`)
Используется для отображения текстовых блоков. Соответствует тегу `<p>`.

```json
{
    "element": "p",
    "id": "lb-1",
    "parent": "lb-root", 
    "styles": {
        "color": "#333333",
        "fontSize": "16px"
    },
    "value": "Текст параграфа",
    "order": 0,
    "deleted": false
}
```

### 2. Контейнер (`div`)
Используется для группировки других элементов и создания макета. Соответствует тегу `<div>`. Не имеет поля `value`, так как служит только оберткой.

```json
{
    "element": "div",
    "id": "lb-2",
    "parent": "lb-root",
    "styles": {
        "display": "flex",
        "padding": "20px"
    },
    "order": 0,
    "deleted": false
}
```

### 3. Ссылка (`a`)
Используется для создания гиперссылок. Соответствует тегу `<a>`.

```json
{
    "element": "a",
    "id": "lb-3",
    "parent": "lb-2",
    "styles": {
        "textDecoration": "underline"
    },
    "value": "Перейти на сайт",
    "src": "https://example.com",
    "order": 0,
    "deleted": false
}
```

### 4. Изображение (`img`)
Используется для вставки графики. Соответствует тегу `<img>`. Поле `value` содержит URL изображения.

```json
{
    "element": "img",
    "id": "lb-4",
    "parent": "lb-2",
    "styles": {
        "width": "100%",
        "height": "auto"
    },
    "value": "https://cdn.example.com/image.jpg",
    "alt": "Описание изображения",
    "order": 0,
    "deleted": false
}
```

### 5. Кнопка (`button`)
Используется для интерактивных элементов действия. Соответствует тегу `<button>`.

```json
{
    "element": "button",
    "id": "lb-5",
    "parent": "lb-2",
    "styles": {
        "backgroundColor": "#007bff",
        "color": "#ffffff"
    },
    "value": "Перейти на страницу",
    "src": "https://example.com",
    "order": 0,
    "deleted": false
}
```

> Примечание к полям:
>- `id`: Уникальный строковый идентификатор элемента в формате lb-<номер>.
>- `parent`: Идентификатор родительского элемента. Для корневых элементов указывается как `root`.
>- `styles`: Объект key-value, содержащий CSS-свойства.
>- `deleted`: Флаг удаления. Если true, элемент считается удаленным.
>- `order`: Порядок следования элементов в родительском контейнере. Так как один контейнер может быть вложен в другой, `div` тоже присуще это свойство.

## Логика вложенности
Отношение вложенности определяется не порядком в списке, а значением поля parent.
Элемент **A** считается вложенным в элемент **B** тогда и только тогда, когда `A.parent == B.id`.

*Визуальное позиционирование:* В визуальном редакторе физически элементы располагаются иначе с использованием абсолютного позиционирования. Однако логическая структура дерева строится строго по идентификаторам родителей. Это позволяет отделять структуру документа от его визуального представления.

*Различие между визуальным и логическим представлениями:* Логически элементы располагаются следующим образом:
```html
<p id="lb-1">Пример текста</p>
<div id="lb-2">
    <a id="lb-3" href="https://example.com">Перейти на сайт</a>
    <div id="lb-4">
        <p id="lb-5">Заголовок картинки</p>
        <img id="lb-6" src="./example.png" alt="картинка-пример"/>
    </div>
</div>
```
В поле редактора элементы располагаются следующим образом:
```html
<p id="lb-1">Пример текста</p>
<div id="lb-2"></div>
<a id="lb-3" href="https://example.com">Перейти на сайт</a>
<div id="lb-4"></div>
<p id="lb-5">Заголовок картинки</p>
<img id="lb-6" src="./example.png" alt="картинка-пример"/>s
```
Таким образом, при перемещении элементов в редакторе меняются только их свойства `left` и `top` (`div` дополнительно задается `height`, чтобы элемент был визуально помещен в него), а порядок элементов не меняется.

## Обоснование выбора формата
Выбор плоской структуры списка объектов вместо классического вложенного JSON-дерева обусловлен следующими архитектурными преимуществами:
- **Эффективность частичных обновлений:**
При редактировании лендинга пользователем изменяется лишь малая часть элементов. Передача всего дерева при каждом изменении неэффективна по нагрузке на парсер. Плоский список позволяет отправлять на бэкенд только массив измененных объектов, где каждый объект самодостаточен.
- **Упрощение операций CRUD:**
    - **Создание/Удаление:** Добавление нового элемента требует лишь генерации нового ID и указания `parent`. Удаление реализуется через установку флага `deleted: true` без необходимости перестройки всего дерева на клиенте.
    - **Перемещение (Drag-and-Drop):** Для переноса элемента из одного контейнера в другой достаточно обновить одно поле — `parent`. В случае с вложенным деревом потребовалось бы вырезать узел из одной ветки и вставлять в другую, что сложнее алгоритмически и затратнее по ресурсам.
- **Независимость от порядка сериализации:**
Порядок элементов внутри одного родителя определяется отдельным полем order, но не структурой JSON. Это упрощает сортировку и перестановку элементов интерфейса.
- **Совместимость с реляционными и документными БД:**
Такой формат легко мапится как на документы MongoDB, так и на таблицы SQL. Это дает гибкость при выборе хранилища на этапе масштабирования.
- **Безопасность и валидация:**
Наличие явного поля `element` позволяет строго типизировать данные на бэкенде и применять разные схемы валидации для разных типов узлов (например, проверять URL для `img` и `a`, но игнорировать его для `p`).
- **Простота получения HTML:**
По данному формату несложно можно получить искомый HTML страницы.
